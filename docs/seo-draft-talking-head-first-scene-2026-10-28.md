# Draft: Choose the first visible scene for a presenter-led SaaS video

**Unpublished planning draft.** Original evidence required before release: Owned opening variants with clear task orientation and review notes. Fictional examples are labeled; they are not actual customer outcomes.

## Choose what the opening must establish

The first scene should orient a viewer to a specific software task and give a reason to continue to the demonstration. Decide whether the viewer needs a spoken problem, a question or an immediate instruction. Each option should lead to the same supported product action.

## Three fictional opening scripts

For a fictional call-note feature: problem opening, “the call ended and you need the next step”; question opening, “where did the action from the call go?”; instruction opening, “open your project note before the follow-up.” These are writing options, not owned recordings or tested hooks.

## Pair each opening with proof

Show the project, open the relevant note and hold its next-step section. If the real product uses a different workflow, rewrite the lines to match it. Do not imply that the software writes or sends a follow-up unless the demonstrated feature actually does so.

## Review the actual first scenes

Record permissioned variants only when available. Ask a reviewer what task each opening sets up, then save real feedback and exact versions. The clearest opening is a review finding, not something that can be inferred from a sample script.
