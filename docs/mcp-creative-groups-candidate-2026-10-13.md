## Implemented contract

`get_asset_group_capabilities`, `list_asset_groups`, `get_asset_group` and `list_asset_group_items` expose the application's actual video/image groups and membership. Paging uses owner-bound cursors and deterministic timestamp/UUID tie-breaks. Detail returns a SHA-256 revision over group metadata and every member identity/addition time, including unavailable members. Membership reads bind that revision and recheck it before returning. Removed/unavailable asset titles remain hidden; ready media delivery uses the existing `get_asset` contract.

`create_asset_group`, `rename_asset_group`, `delete_asset_group`, `add_assets_to_group` and `remove_assets_from_group` use the same application group/member tables, canonical owner/type/readiness triggers and a new service-only transaction/receipt boundary. Creation uses the caller's UUID as stable group identity. Later writes require the exact saved revision, so website name or membership changes reject stale agent intent. Add/remove batches are bounded to 100 distinct media IDs. All additions must be ready, owned, visible Creative Assets matching the group's media type; invalid batches roll back in full. Existing application group handlers/constraints remain unchanged. Delete removes the group/membership, preserves all media and has no normal application undo; it requires an explicit user request.

`get_asset_group_request` recovers the immutable accepted receipt, including after newer website edits/deletion or disabled writes. Replay returns the same historical result and never reapplies older changes. `list_asset_group_requests` discovers lost request UUIDs through owner-scoped metadata. No provider, renderer, billing or media bytes are involved. Existing `assets:read` / `assets:write` permissions are checked before storage, and the consent copy includes group organization.

`MCP_CREATIVE_GROUPS_ENABLED=false` by default. Capabilities separately report the gate and configured storage and explicitly require schema verification; a gate value is not proof of migration/readiness. No private-upload/audio gate or infrastructure is activated.

## Additive local schema

CLI-generated `20261013035507_mcp_creative_asset_groups.sql`, SHA-256 `25942a904843d828600dee840e225d3855d15446cf65389e1885cc4ed5335508`, adds immutable owner/request receipts, service-only invoker snapshot/mutation RPCs with empty search paths and deterministic paging indexes. Request fingerprints are computed from normalized operation/input inside PostgreSQL, including sorted UUID batches. Matching request locks recover accepted results; group/member/asset row locks protect stale revisions and full-batch validation. Existing group triggers are retained. Browser roles cannot execute the new functions or read receipts. Service role can read/insert receipts but cannot rewrite them. No migration has been applied.

Read-only production inspection confirms existing group/member RLS and service-only reads.
