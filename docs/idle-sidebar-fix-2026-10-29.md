# Idle sidebar recovery — local implementation

Incident: UGC-UI-050. Local scope implemented; authenticated production idle acceptance remains OPEN. The user's reported production cause remains unconfirmed. This patch corrects the reproduced profile failures and provides explicit recovery from the reproduced stalled-route failure path; it does not alter Next's internal fetch implementation or guarantee that a broken connection will resolve.

## Behavior

- Sidebar (expanded, collapsed and mobile) and Explore entry links retain Next Link navigation, destinations, prefetch and keyboard/modified-click handling. Only an accepted client navigation starts feedback. The shared shell shows a temporary opening status; after 15 seconds without a URL commit it offers a normal browser link to open the destination in a new tab. Current edits stay in the original tab. There is no forced reload, automatic new tab, paid action replay or cache-duration change. A new requested destination replaces the old notice, any pathname/query commit clears it, and provider unmount clears its timer. The notice survives the mobile drawer closing.
- Profile reads now bind token acquisition to the query owner and check cancellation before fetch. A token resolving after cancellation cannot start fetch. The existing 20-second deadline remains.
- An account-scoped successful onboarding check remains usable through a typed temporary network/upstream failure or deadline. Initial failures, unknown errors, 400/401/403, signed-out/unverified users and a confirmed incomplete profile still block or redirect through the existing guard. Server API authorization is unchanged. Cache freshness/retention and retry policy are unchanged.
