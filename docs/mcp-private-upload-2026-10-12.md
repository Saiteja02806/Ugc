## Behavior and boundary

`create_upload` can reserve private input media when the explicit MCP-only `MCP_PRIVATE_UPLOADS_ENABLED=true` gate is accepted. The global website `PRIVATE_USER_MEDIA_ENABLED` cutover is unchanged: an unset/false global gate keeps website uploads on their current path. If the global private gate is on without the new MCP gate, MCP still fails closed. Creation checks a separate `GCP_PRIVATE_MEDIA_BUCKET`, bucket-level enforced public access prevention, private delivery signing readiness and HTTPS application origin before reserving. No IAM policy mutation, public fallback or inferred inherited policy is permitted.

The additive service-only invoker `mcp_reserve_private_upload` wraps the existing reservation/quota transaction and commits `storageLocation=private_user_media` in that same transaction. It does not retag an existing request or relocate existing public/private objects. Exact old signatures remain unchanged; fingerprints, original stable UUIDs, shared quota and deletion replay guards persist. Lease/confirmation/probing and cleanup follow the persisted row location and canonical URL, independent of creation selection. A configuration change that no longer matches that private URL fails rather than silently addressing a different bucket. Confirmation remains available when new creation is disabled.

Private signed PUTs preserve size and create-only signed headers. An optional `storage_bucket` descriptor is emitted only in the signed reservation/renewal response; read-only upload summaries still omit storage URLs/keys/location details. The 0.1.8 helper accepts that exact server-described bucket and reserved collection/ID, and keeps old public receipts on the original production default. Caller-supplied descriptors are not accepted by MCP, and the helper must not be given an edited descriptor to bypass a rejection. Ephemeral signed URLs stay on stdin; local intent/transfer receipts remain non-secret.

Private probing reads checked generation-pinned bytes through the existing private reader, enforces measured size/MIME/container/dimensions/duration, cancels rejected streams and uses restricted local ffprobe. It does not fetch caller URLs or fall back to public storage. Pending private cleanup requires the selected row to be an owner-deleted MCP upload; tombstones use checked-generation compare-and-swap or create-only occupancy, and cleanup deletes that checked generation only after the existing renewable-lease grace/claim. Active, ready or non-MCP rows are rejected. Missing/failed policy checks or the disabled MCP gate leave cleanup pending/counting quota. This is implementation of a new explicitly gated MCP writer, not the previous no-delete migration pass. Historical source-copy/migration scripts and generic website guards are unchanged.

Private inputs can feed the existing Explore/edited-video worker private-reference paths. Generated/finished outputs retain the application's existing output-storage policy; this step does not claim end-to-end private output storage, browser-wide token renewal or the wider private-media cutover.
