# Image role and labeling audit — 28 October 2026

**Result: PARTIAL / a material Talking Head handoff gap is present in the current local code.** This is a code and fixture audit, not proof of live provider acceptance or generated visual fidelity. Current working tree contains uncommitted changes including the carryover hook and generation contracts; deployed behavior may differ.

## Main finding: Talking Head does not automatically carry the original identity photos

The completed starting-frame selection includes `identityAssetIds` copied from the approved request (`components/explore/hook-starting-frame-workspace.tsx`, `selectStartingFrame`), and recent-frame recovery rebuilds them from the owned generation receipt (`lib/explore/hook-starting-frame-history.ts`). The frame itself and its original identity photos therefore have separate recorded identities.

The Hook video composer (`components/video/video-generation-workspace.tsx`) calls `useStartingFramePhotos`: on a supported model it resolves those IDs through the owned media API and restores their order. Explicit per-frame user changes, including an empty selection, override the receipt fallback. A missing photo is reported and generation is blocked while it is unresolved. This is validated in `scripts/starting-frame-photo-carryover.test.mjs`.

The separate Talking Head + Demo composer (`components/explore/hook-workflow-preview.tsx`) stores `facePhotos` in local React state initialized to an empty array. `approveStartingFrame` saves the frame but does not read `frame.identityAssetIds`, call the restoration hook, or clear an existing face-photo selection when replacing the frame. It submits that independent `facePhotos` array. Consequently the original photos are **not automatically carried forward in this path**, and a previously selected photo list can persist across a change to another frame until explicitly cleared. The project records this carryover requirement, so this discrepancy is actionable. A tested fix must restore the current frame’s owned IDs, respect explicit additions/removals, cancel stale async reads, and avoid mixing photos across frames. No fix was requested or applied in this report.

For example, if a user supplied three identity photos to create a new starting frame, the image-generation request has the source scene as Image 1 and the three identity photos as Images 2–4. In a supported Omni video request that actually includes those same three photos, the **generated starting frame becomes video Image 1** and those photos become video Images 2–4. The numbered labels change because the transmitted inputs have changed; the photos remain face references. An earlier variation keeps its own receipt; the selected successful frame’s receipt is the relevant one.

For v7 starting images, Gemini Pro and Nano Banana attach verified labels alongside image inputs; OpenAI and Seedream receive ordered inputs and role descriptions in the compiled prompt (OpenAI also receives label-derived filenames where supported). The semantic result depends on the external model following those instructions. `worker/src/lib/gemini-omni-video.ts` constructs the Omni numbered markers and ordered image array; the provider request is the tested code path, not evidence that every model produced correct faces.

## Follow-up: Talking Head handoff fixed locally; expanded route audit

The earlier Talking Head gap above describes the pre-fix state. `hook-workflow-preview.tsx` now invokes the same owner-bound `useStartingFramePhotos` restoration used by Hook. Photo state is keyed by approved owner/job/asset; the request uses only the current frame's photos and omits optional photos for unsupported models. Restoring or failed photo reads block submission; explicit edits/removals are persisted by the shared hook. Frame changes cannot submit the previous frame's photo state. Existing generation request validation and provider mappings are unchanged. `scripts/workflow-demo-audio-state.test.mjs` exercises the actual parent with a controlled hook boundary for restore/pending/error/selection/frame change/model change; `scripts/starting-frame-photo-carryover.test.mjs` independently exercises the real async hook, owner reads, empty choice, reload, stale abort and missing media. Combined tests do not replace an authenticated live end-to-end run.
