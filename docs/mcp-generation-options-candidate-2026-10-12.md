## Implementation

- `get_generation_options`: account-scoped read of current application models, quality, durations, format-specific reference limits, price, plan/runtime/provider availability and a separate creation gate. It does not initialize credits or generate samples.
- `generate_image_with_options`: Studio model choice plus slideshow image models/ordered style references, attachments and an existing slide edit target through the application's same image parser and frozen role contract.
- `generate_video_with_options`: all four application video models, their supported quality/durations, ordered owned image/audio/video references and Hook/Wall-of-Text workflow options. Gallery references resolve from the existing server catalogue and measured source duration. The shared validator derives paired soundtrack provenance; arbitrary provider URLs or soundtrack objects are not accepted.
- `get_generation_request`: owned advanced-batch discovery by saved client UUID, including interrupted responses and partial children. Read-only after plan/gate/reference changes; never dispatches work. `get_job` and existing asset delivery retrieve accepted output IDs.

Both website handlers retain their Firebase authentication/access-before-body behavior. They call extracted server-only owner entry points, reused by MCP after scope/account/access checks. The shared image input builder supplies the same fields to website submission and the atomic adapter. No MCP token is passed through Firebase HTTP. Legacy image/video schemas, fingerprints and strict V1 reservation behavior are retained. Only new advanced submissions initialize the existing lifetime free-credit allocation like website generation; catalogue/recovery reads and legacy calls keep their prior read policy.

Creation requires `MCP_ADVANCED_GENERATION_ENABLED=true`, default false. An additive service-only invoker RPC uses the existing billing and job functions in one transaction, an empty search path, account/batch advisory locking and four exact sibling keys. Existing strict V1 RPC is unchanged. Partial siblings must match both the normalized request and validated reference/role/timing/price snapshot; changed resolved URLs or saved reference metadata cannot silently alter later outputs. Matching full replays can recover a queued delivery without creating jobs/reservations. All siblings validate before dispatch. A partial retry still needs enabled creation, current access and valid unchanged references. A conflict does not authorize a replacement request.

The application sometimes normalizes unsupported numeric durations; the advanced adapter explicitly rejects durations absent from the selected model's advertised set, preserving user intent. Long Omni instructions remain exact. Foreign/deleted/unready/wrong-type references fail before billing. Private audio-library IDs remain separate from generic editing/generation media IDs. Reference metadata fingerprints are not an independent proof of immutable provider bytes after queueing; the existing worker's reference retrieval remains authoritative.
