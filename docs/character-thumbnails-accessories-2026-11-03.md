# Character loading and optional accessories — 3 November 2026

Implemented in the worktree; cloud thumbnails uploaded and verified. **Not deployed. No build, dev server, browser fixture bundling, push or paid generation was started.**

## Findings and changes

Hairstyle and outfit cards resolved to the full catalog originals through Next Image optimization. The 23 hairstyle originals total 27,076,403 bytes and 29 outfits total 33,528,034 bytes. Those are unnecessarily heavy upstream sources for small cards, especially on a cold optimization request. The user's exact browser latency/network cause was not captured; this finding establishes source weight and an avoidable processing dependency.

Published maximum-384-pixel WebP thumbnails for all 132 catalog paths to content-addressed immutable objects in `gs://ugcsaas-media/catalog/character-studio/thumbnails/v1/`. Every resulting public HTTPS download was SHA-256 verified against its generated bytes. Metadata records original source hash, output hash, dimensions and size. Card rendering now uses those small backend images directly, bypassing the Next optimizer. Personal uploaded photos keep their existing URL behavior. Lazy loading and existing card geometry/CSS remain intact.

| Catalog group | Original sources | Thumbnail sources | Reduction |
| --- | ---: | ---: | ---: |
| Hairstyles, 23 | 27,076,403 bytes | 281,682 bytes | 98.96% |
| Outfits, 29 | 33,528,034 bytes | 171,128 bytes | 99.49% |

These are asset-transfer comparisons, not measured page-load improvements; the previous optimizer may already have reduced browser transfer on warm requests. All thumbnails are below 80 KB and at most 384×384. Full originals, generation preparation URLs/hashes, owner reference identities and legacy catalog redirects are unchanged.

Accessories now have a **No accessories** card selected by default. The existing empty `accessoryIds: []` representation remains the source of truth. Clicking None clears multiple selected accessories. Choosing an accessory deselects None; removing the final accessory restores it. Existing multiselection remains supported. Reset returns to None, and randomization may also choose None. The UI-only None trait has no image/reference and never occupies a model reference slot. Empty accessory selections explicitly request no accessories in new prompts; explicit selections retain their previous instructions. Frozen historical requests are not modified.
