# Demo controls

Release implementation for Create Hook and Creator Shows App on Phone. Production rollout is tracked in the release receipt.

The compact outlined **Demo controls** button uses a controls icon and aligns right beneath the selected demo's preview, alongside the filename. The filename truncates; narrow panels allow the button to wrap while retaining right alignment. Saved framing adds a small status dot with accessible text and an adjacent reset button. The modal shows the complete source with a draggable frame and a live cropped output. Position/zoom first, then **Record movement** from time zero. Mouse/touch dragging and arrow keys are recorded against media playback time. **Stop recording** holds the last position for the remainder; it never trims the demo. **Review**, **Save framing**, **Cancel** and **Reset framing** are explicit. Cancelling leaves the previously saved path untouched. Successful demo replacement/removal clears the old path; an invalid replacement preserves it.

The viewport shape follows the selected generated video's dimensions, with generation aspect settings used before a video is selected. Preview and render use the same linear interpolation between time/position samples; no implicit jump between crop endpoints and no artificial easing that changes drag speed. Dimensions remain fixed during a recording. Only the demo is reframed; opening, original speech/audio, subtitles, source uploads and duration retain their existing behavior.

The optional `demoFraming` field is a versioned object with normalized width/height and `[demoTimeMs,x,y]` samples. It is omitted entirely for legacy drafts, preserving old fingerprints/recovery. Paths are strictly bounded (120 seconds, 512 saved samples, monotonic times starting at zero, in-bounds positions). Compaction retains playback timing and bounds reconstruction error; excessive complexity is reported rather than silently truncated. Render validates the real decoded dimensions/duration and crop aspect before output or transcription. A numeric-only balanced expression tree is written to the new render directory to avoid shell injection, recursion depth and platform command-line limits. The recorded path is included in the owned receipt/fingerprint/output metadata.

`EXPLORE_DEMO_FRAMING_ENABLED=true` is required on the application server before production UI or new framing requests are enabled. It is enabled only after the compatible workers pass startup and configuration verification. Explicit development layout previews expose the controls without uploads, generation, render requests or credits. Deployment order: matching worker first, production gate on the website project, app built from the reviewed commit, then checks against the real production domain. The old app ignores the additive gate while its replacement builds. Disabling the gate stops new framing requests; keep a compatible worker while draining/recovering already accepted requests. No SQL schema change is needed: the existing owned draft JSON stores the additive field.

Release files were staged from a snapshot and updated only after comparing original hashes. Unrelated local edits were not overwritten. Desktop source files were not replaced with the isolated checkout.

The original implementation baseline passed worker build, application TypeScript, optimized Next.js build, scoped ESLint and diff checks; 149 focused/regression tests across contract/recording, API ownership and gates, receipt recovery, both workflows, audio, rendering and storage. Real FFmpeg exports verify holds, gradual movement, demo-relative timing, original speech, total duration, unchanged input files, invalid path rejection and the 512-sample limit. The worker tests verify framing reaches both rendering and saved metadata; legacy jobs omit it. These build results predate the audit fixes below.

Installed headless Chrome verified real file selection, live dragging/recording and replay, Save, reopen, Cancel, Reset, accepted replacement, removal, and a 390px layout in explicit local preview mode. Eleven browser flow checks passed without page errors. A Strict Mode source-detach issue was caught and repaired before completion; controls wait for the decoded frame before becoming available. Touch uses the same pointer-capture path but physical touch-device acceptance has not been performed.

Signed-in storage/render acceptance and real mobile-device acceptance remain pending. The user explicitly deferred signed-in production checks; this release does not generate paid media or publish posts for verification. Local preview evidence is retained in the desktop checkout's ignored task folders; generated artifacts are not release source files.

Audit on 2026-10-06 reproduced and repaired a stale paused preview, an outside player continuing during editing, and high-frequency pointer samples exhausting the recording budget after 16.4 seconds. Streaming sampling now retains movement at the renderer's 30fps timestamps across the full two-minute limit before bounded simplification. Both workflows prevent incompatible framing from being submitted after video shape changes; reframing or resetting resolves the error before uploads or rendering. Metadata guards remain disabled after invalid loadeddata events. Obsolete playback promises cannot invalidate a stopped recording or update a closed editor.

All audit fixes and the final right-aligned button UI were applied to the isolated checkout using guarded hash comparison. The complete reviewed checkout passed the optimized Next.js build, worker build, 400 Explore checks, 110 media/Audio checks, 103 worker checks, and the full MCP suite. Scoped lint has no errors (two existing unused-variable warnings); diff whitespace checks pass. Real browser tests pass for both workflows: recording, replay, Save, Cancel, Reset, accepted replacement, invalid replacement preservation, removal, Escape cleanup, and paused-preview updates. Footer alignment and overflow checks pass at 1366px, 1024px and 390px; touch emulation moves the frame. No page errors were observed. Physical-device testing remains pending.
